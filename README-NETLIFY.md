# Bashid Store — публикация на Netlify

Это статический сайт, сборка не нужна. Загрузи распакованную папку через Netlify **Deploy manually** или подключи её как Git-репозиторий. Если Netlify запросит настройки сборки, оставь команду сборки пустой, а папку публикации укажи `.`.

## Включение гостевой публикации

Регистрации и Google-кнопки в интерфейсе нет. При первой публикации пользователь проходит Cloudflare Turnstile; Supabase создаёт для браузера гостевую сессию. Она не просит имя, почту или пароль. При очистке данных браузера сессия теряется, и проверку нужно пройти снова.

1. В Cloudflare создай Turnstile widget для домена Netlify и скопируй Site Key и Secret Key.
2. В `config.js` замени `REPLACE_WITH_TURNSTILE_SITE_KEY` на Site Key. Это публичный ключ.
3. В Supabase открой **Authentication → Sign In / Providers** и включи **Allow anonymous sign-ins**.
4. В Supabase открой **Authentication → Settings → Bot and Abuse Protection**, включи CAPTCHA, выбери Cloudflare Turnstile и введи Secret Key. Секрет хранится только в Supabase и не должен попадать в `config.js`, `app.js` или архив сайта.
5. Если Google-провайдер включён в Supabase, отключи его там, чтобы полностью закрыть старый способ входа. Это не удаляет существующие аккаунты.

Точная навигация в панели Supabase может отличаться. Для локального просмотра добавь `localhost` в разрешённые домены Turnstile. Открытие `index.html` напрямую не подходит для CAPTCHA и сессий; используй локальный веб-сервер.

## Хранилище и публикация

Загрузка файлов остаётся защищённой RLS: каждый файл хранится в папке гостевой сессии, а публичная роль `anon` не получает право загружать файлы напрямую. Установщики до 500 МБ делятся на части; обложки и видео — до 50 МБ. Файлы и записи занимают квоту Supabase Storage.
